### Shared route behavior

- The `(app)` layout requires a signed-in session, then reads preferences. Before timezone confirmation it shows only the confirmation form, hiding navigation and page content. It owns the sole `<main id="main">`, skip link, toast host, global Quick Add and navigation.
- Current shell: seven equally distributed destinations on a fixed phone bottom bar; desktop sidebar from `md`; Plan's nested destinations are sidebar subitems and a page subnav. Safe-area padding exists for the bottom bar. The redesign decision proposes Home/Plan/Track/More on mobile and a More destination surface; this is target direction, not current behavior.
- Route-level `Suspense` loading exists on most data pages; root `src/app/loading.tsx` is the general loading fallback. Specific error boundaries exist for Home; Goals list, archive, areas and detail; Plan root, Today, Upcoming, Inbox and Calendar; Track and Archived habits; and Review (including history). Other route failures reach `src/app/error.tsx`. Root `not-found.tsx` is public-styled; goal, note and review detail routes provide in-shell not-found boundaries. `src/app/(app)/notes/error.tsx` covers the Notes routes. No route-specific Settings error boundary was found.
- App pages and server actions re-check authentication; layout is not the authorization boundary. Query/action reads and writes are user-scoped. Do not change these guarantees as part of UI work.
- Hash contracts: Track's `#habit-<id>`, Today's `#today-<section>` (linked from Home) and Home's `#goals-without-next-action`. Note search terms are intentionally POSTed, not placed in query strings, per ADR 0016.

## Existing accessibility and E2E coverage

Coverage is substantial but is not a completed app-wide accessibility certification. The repository has `@axe-core/playwright` helper `expectNoSeriousViolations`, route/journey E2E specs, keyboard checks, unit tests for primitives/navigation, and integration tests for query/service/action behavior. The progress log documents axe and keyboard passes for the shell, calendar grids/area views, habit history, review flows/history, notes editor, and note links. `tests/e2e/shell.spec.ts` checks shell/not-found and timezone-confirmation pages; Home, Track, Review, Preferences, Goals, Plan, Notes and their detailed routes have dedicated feature coverage. Do not infer that every route, viewport, color theme, or manual screen-reader flow has been audited.

Evidence limits and known follow-ups from the implementation log:

- The 10.5 app-wide accessibility pass is todo; its planned work includes axe on every page, journey keyboard walkthroughs and screen-reader spot checks.
- Latest 8.3 handoff says no manual screen-reader or manual dark-mode pass. Automated axe success is limited to assertions in named tests and does not prove all pages/contexts pass.
- No visual regression/screenshot test suite or phone/tablet × theme screenshot set was found. Feature E2E tests mostly establish behavior, not responsive visual quality.
- Theme implementation is verified in `src/app/globals.css`: light is the base, dark follows `prefers-color-scheme`, and `data-theme="light|dark"` can override it. Root layout does not set `data-theme`; no Settings theme selector or preference persistence is wired in inspected code. The supplied current captures are described as dark in `DESIGN_DECISIONS.md`, but their viewport and whether dark came from OS or explicit override are **unverified**.
